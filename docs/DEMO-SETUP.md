# Safe local demonstration

Use an isolated checkout and virtual environment. Install the requirements as described in the root README. Do not copy production configuration or data.

The actual application includes a fixture server that creates an isolated temporary SQLite library, synthetic EPUBs, and cached synthetic tone audio. It starts neither a production TTS job nor a remote import:

```sh
NATIVE_FIXTURE_BOOKS=2 python NativeReader/Tools/fixture_server.py
```

Open `http://localhost:18765` for the real web application with test content. The content is generated by `tests/fixtures.py`, not copied from a private library. Its tones test decoding and queue behavior, not voice quality. The fixture directory is temporary and disposable; do not run a fixture against production storage.

For the iPhone client, use macOS and Xcode. Build an unsigned Debug simulator app, then launch it with the explicit fixture argument:

```sh
xcodebuild build -project NativeReader/WebnovelReader.xcodeproj \
  -scheme WebnovelReader -configuration Debug \
  -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath /tmp/webnovel-demo-build CODE_SIGNING_ALLOWED=NO
xcrun simctl install booted /tmp/webnovel-demo-build/Build/Products/Debug-iphonesimulator/WebnovelReader.app
xcrun simctl launch booted com.parampathak.WebnovelReader --fixture
swift test --package-path NativeReader
```

Use a dedicated simulator. This Debug launch uses localhost, a fixture-specific journal and a fixture audio cache, not the normal backend origin or listening journal. No signing identity or physical-device installation is needed. `--fixture` is a test mode, not a public authentication bypass or production deployment setting.

The portfolio screenshots use original demonstration fiction and covers in the same isolated architecture. They are actual app captures, not generated UI mockups. Real online narration requires the separate configured provider and rights to narrate the selected text.
